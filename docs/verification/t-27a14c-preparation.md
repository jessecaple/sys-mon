## Technical design and named consumers

Create `src/lib.rs` with a public `telemetry` module; keep Linux parsing, hwmon selection and worker ownership in private children. The small public model is `Snapshot` with typed CPU, memory, swap, GPU, network and primary-storage fields. Each measurement is `Reading<T>` (`Value` or `Unavailable`) with explicit unit and optional capacity/threshold. Unavailable never borrows a previous displayed value. GPU, network and storage start unavailable until their owning tickets supply providers. They are named contract fields, not simulated data.

The synchronous test seam is provider sampling with injected source responses and monotonic `Duration`: `HostSampler::tick` produces a **host-only patch** for CPU usage, RAM and swap; `TemperatureProvider::sample` produces a **temperature-only patch** from its bounded helper process; the helper's hwmon scanner has injected-directory fixtures. Neither returns a complete Snapshot. The production Linux host probe reads `/proc/stat` and `/proc/meminfo` independently. The temperature probe enumerates hwmon channels anew and selects an attributed reading. Public session tests drive controlled provider patches and inspect `TelemetrySession::snapshot()`, with parser fixtures only where they add source coverage.

`TelemetrySession::builder()` registers provider factories before `start`; `start_system()` installs host and temperature providers. Each registered provider has an owned worker, a field-scoped patch type, a bounded sampling contract and an interruptible one-second default delay after work. Registration rejects intervals below 10 milliseconds, including zero, and caches the exact validated duration so a later provider change cannot create a busy loop. The session accepts an injected monotonic clock for deterministic public-snapshot tests of invalid and resume intervals; production uses `Instant`. An injected clock must respond to cancellation. The session retains worker handles, cancellation signal and owned helper handles; later GPU and network/storage tickets add providers through the builder rather than creating unregistered writers. Each worker samples without holding the snapshot lock. Host reads are cooperative procfs operations. Optional temperature sampling invokes a self-contained helper process running this executable in a hidden internal mode. The helper owns the potentially stuck hwmon read; the parent waits only to a bounded deadline, kills on timeout and publishes unavailable. It never starts a second helper while an old one is unreaped. On stop it kills any active helper and performs bounded reaping, without waiting on an unreleased read. A kernel task stuck in uninterruptible sleep is an OS limit: retain one child handle, never multiply it, and do not block window close; normal killable stuck-user-space helpers must terminate in the process-boundary test. The GPU ticket must use this killable helper pattern for potentially unbounded vendor calls, not raw FFI in a cooperative worker.

`SnapshotState` holds `{active, generation, latest}` under one `Mutex`. A provider publishes a typed `Patch::{Host,Temperature,Gpu,NetworkStorage}`; `apply` replaces only its owned fields. Snapshot cloning and patch application hold the lock briefly. `stop` takes that same lock, sets `active=false` and advances generation, then releases the lock before wake/kill/join. A late patch, including one that passed a cancellation check earlier, is rejected inside `apply` when inactive or from an old generation. No I/O, helper wait, GTK code or thread join occurs under the snapshot lock. Interleaving host and GPU/I/O patches cannot erase each other's fields. A provider panic is caught at the worker boundary, publishes unavailable for its owned fields, and retries at bounded pace. A poll error likewise replaces only its own fields with unavailable, then can recover on a later tick. `stop` and `Drop` are idempotent; stop terminates every registered provider and its owned helpers. No queue stores obsolete snapshots. Work and retained state scale with currently registered/discovered devices, not uptime.

The dashboard ticket reads `TelemetrySession::snapshot()` on GTK's main loop and calls `stop` when the only window closes. The GPU ticket owns vendor providers and helper implementation. The network/storage ticket owns rate baselines, current device identities and filesystem identity. Public contract changes affecting those consumers require comparison on integration refresh. There are no network/database resources or migrations.

## Readiness and verification map

- Source fixtures exercise host-only patches applied through public snapshots for CPU warm-up/reset, guest accounting, steal convention, RAM/swap units, real zero and unavailable.
- Controlled probe errors and hwmon sets exercise independently unavailable fields, Tdie selection, multiple packages, fault, max-versus-crit and crit-only scales, removal and recovery.
- Controlled `/proc` source frames and injected elapsed time flow through the public session snapshot, including permission failure and recovery. Repeated hwmon arrival/removal and a scripted helper flow through session snapshots, proving no stale sensor state or retained helper processes. Controlled provider interleaving proves host publishes preserve GPU/I/O fields. A late publish racing stop is rejected; repeated stop and helper termination are observable at the session/process boundary.
- A slow host source shows no overlapping host polls or catch-up. A never-released optional helper shows host CPU/RAM continue, at most one child exists, and stop returns without waiting for that helper; normal killable helper is reaped.
- On the available host, compare RAM/swap to `/proc/meminfo`, CPU usage to consecutive `/proc/stat` samples, and CPU temperature to attributed `coretemp`. These are plausibility checks, not vendor coverage.
- `cargo fmt --check`, `cargo test`, and `cargo clippy --all-targets -- -D warnings` qualify the implementation. No native UI exists in this ticket; visual and accessibility QA belongs to M2.
