## Technical design

Add a private GPU module under `telemetry`; `GpuProvider` implements the existing `ProviderKind::Gpu` patch owner. `TelemetrySession::start_system` registers it. The dashboard consumes only `Snapshot.gpu`; no public model or migration change is planned. The GPU provider invokes this executable in `--internal-gpu-probe` mode. A child returns one bounded, versioned record per discovered device, with independent status for usage, VRAM and temperature; the parent parses it, selects one device and publishes a `GpuPatch`. A child exit or malformed output yields unavailable GPU fields. Vendor libraries and sysfs reads occur in the child, never on the session worker or GTK loop.

The parent enforces a short sample deadline, kills a late child, and does not spawn a replacement until the previous child is reaped. It retains at most one child handle and a bounded output buffer. `stop` cancels the wait, kills the child, rejects late patches through the existing generation gate, and joins the worker. A kernel task stuck in uninterruptible sleep may resist reaping; the provider keeps that one handle rather than multiplying children or delaying window close. Vendor discovery, sampling and independent query failures happen anew on each child invocation, so recovery requires no process restart. No shared mutable vendor state, queued frames, database or schema exists.

For Intel Sysman, load the library and required symbols at runtime within the child. Use ABI-compatible C structures for only the queried properties, check return codes and bounds before using outputs, enumerate each handle set twice only as the ABI requires, and reject unreasonable counts. Query the aggregate engine twice with a short interval in the same child so no counter survives identity churn. Reject a reset, equal timestamp, active delta greater than timestamp delta or nonfinite result. Add only device-local memory modules with checked arithmetic; any failed module query makes VRAM unavailable rather than reporting a partial total. Prefer a GPU temperature sensor over a global sensor, preserving source type and a valid positive hardware maximum where exposed. NVIDIA uses runtime-loaded NVML; AMD uses sysfs. Each field remains independent.

The helper executes at the existing one-second provider cadence, without catch-up or overlap. Its process output and discovered list are bounded by a fixed maximum device count and bytes; the parent never appends history. The initial source base is the integrated `src/telemetry/mod.rs`, `src/telemetry/linux.rs`, `src/main.rs` and `tests/telemetry.rs`. The active I/O ticket and later GTK dashboard are named consumers of the same session contract; this ticket changes only GPU-owned fields and registration.
