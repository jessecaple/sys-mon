## Technical design and readiness

Add one `IoSampler` provider registered by `TelemetrySession::start_system`, with an injected `IoProbe` for source frames and capacity responses. Keep proc/sys parsing and mount selection private. It returns an `IoPatch` per tick, using independent network, block and capacity results. Add `PrimaryVolume.used_bytes` to the public type for the dashboard's used rail; existing `available_bytes` remains the visible amount. The current session already serializes each provider, coalesces to the latest snapshot, and stops on cancellation. `/proc` and sysfs reads and `fstatvfs` are synchronous local calls of the same class as existing host reads; this ticket adds no foreign driver helper or new worker protocol.

Rate state maps current identity to `(counter, elapsed)` and replaces the map each tick. Failed source reads clear that source's map. A failed individual selected device is not treated as zero. Sum checked deltas only when all selected devices for that direction have valid baselines; otherwise publish `WarmingUp` or the more specific error. Capacity is recomputed each tick without a rate baseline. The dashboard consumes `NetworkSnapshot`, `StorageSnapshot` and `PrimaryVolume`; the latter gains `used_bytes`. No schema migration is needed. GPU/host providers continue to publish independently.
