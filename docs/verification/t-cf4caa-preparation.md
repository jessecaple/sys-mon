The Linux [mountinfo format](https://man7.org/linux/man-pages/man5/proc_pid_mountinfo.5.html) specifies the filesystem type and filesystem-specific source fields; [fdinfo](https://man7.org/linux/man-pages/man5/proc_pid_fdinfo.5.html) links an opened descriptor to a mount ID. The [kernel FUSE overview](https://docs.kernel.org/filesystems/fuse/fuse.html) describes a userspace filesystem interface, so `fuse.*` alone is not proof of network storage. Locality classification is deliberately conservative; a future unfamiliar local type will need an explicit rule before its capacity is published.

## Technical design and readiness

Keep `IoSampler` and `IoPatch` unchanged publicly. Change only its private volume probe/frame and selection: read mountinfo, open each path independently, identify its effective type and avoid `fstatvfs` on remote, unclassified or non-storage mounts. Preserve each path's result, then publish every verified local path. Either path can supply the reading alone. Deduplicate only two classified local volumes with matching device, filesystem type and source. No schema or migration change. M2 is the named consumer of the existing `PrimaryVolume` vector; network/block consumers are unaffected.

The provider remains serial in the existing telemetry session. This changes no shared retry or concurrency protocol. Mutable inputs are current mount namespace and filesystem state; descriptors bind identity and capacity through each sample. Each tick replaces capacity and retains no mount history. Remote filesystems can still delay pathname resolution before `O_PATH` succeeds; this ticket avoids their potentially blocking `fstatvfs` call but cannot promise a deadline for kernel path lookup. That limitation needs disclosure in the evidence.
